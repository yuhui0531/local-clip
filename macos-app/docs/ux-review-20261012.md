# LocalClip UX/UI review — 12 October 2026

Implemented against checkout `b273d17`, starting from a clean working tree. The existing SwiftUI/AppKit components, horizontal card layout, storage model, and clipboard pipeline were retained. No production database was opened by the validation harness; UI testing used the dedicated GUI Check bundle, a temporary test store, and a named clipboard. No migration, installation, commit, push, or publication was performed.

## Findings and changes

| Area | Finding | Implemented improvement |
|---|---|---|
| Visual hierarchy | Saturated card headers competed with content; body text dropped to 9.5 pt on compact cards. | Soft type tints with semantic foreground colors; compact body text increased to 12 pt; slimmer selection ring and system-accent primary actions. |
| Discoverability | Number-key paste shortcuts were invisible; detail icon resembled resize. | Modifier-aware shortcut badges on the first nine cards; recognizable information icon; concise search placeholder and contextual help. |
| Search and empty states | Favorites/type/source/date scopes could show a misleading first-copy message. | Scope-aware guidance, clear-search/clear-filter actions, and a return-to-history action. Fixed stale empty-state rendering when switching scopes. |
| Privacy feedback | Hidden content was an unexplained blurred surface. | Explicit hidden-content state with a reveal button, zero-opacity content, and hidden accessibility descendants. Removes the full-strip blur effect. |
| Recording | A timed pause could leave the toolbar presenting Pause; resuming did not cancel the timer. | State-correct resume icon; a shared resume action clears the timed pause and persists capture enabled. Status colors reflect actual capture state. |
| Keyboard | Command–F opened filters when already editing search; Escape could dismiss the panel during IME composition. | Command–F consistently focuses search. Both search-field and app-level handlers defer composed input to the IME. |
| Settings | One long form made unrelated settings hard to find. | Five directly accessible sections: General, Paste, Privacy, Storage, Advanced. Existing controls and explanatory text retained. Fixed-height feedback area avoids shifts; stored retention/quota changes refresh their drafts; unchanged Apply buttons are disabled. |
| Overflow | Filter popovers expanded indefinitely with category count. | Bounded scrollable form with a separated, always-visible action row. |
| Accessibility and motion | Each card exposed repeated copies of the same accessible action; toolbar hover animations ignored Reduce Motion. | One accessible element per card, preserving the inline rename input while editing; selected-tab and favorite labels; Reduce Motion respected by toolbar hover transitions. |

## Validation

- Debug suite: Swift Testing reports **153 tests, zero failures**, with **19 opt-in tests skipped** in the default run. See [final log](../evidence/ux-20261012/integrated-tests.log).
- Native subset: explicitly enabled named-clipboard/hosted tests; **21 tests reported, zero failures**. Includes every supported clipboard kind through the hosting destination, category routing, title/body hit routing, history loading, and named clipboard privacy/round trips. Some long benchmarks remain opt-in. See [native log](../evidence/ux-20261012/native-final.log).
- New regressions exercise persisted timed-pause recovery, filter reset preserving the search term, and Escape with marked text.
- Actual SwiftUI renders were inspected in light/dark themes, 800×280 compact and 1400×400 normal panels, plus empty, hidden, paused, category-overflow, filter, detail, and settings states. These are native rendered pixels from synthetic data, not mockups.
- Live GUI checks confirmed favorites/category empty-state updates, clear-search recovery, horizontal scrolling, category creation, selection, inline rename, search by the saved title, Command–F, hide/reveal, all five settings sections, timed-pause recovery, and a single accessible element per card. The isolated app was closed afterward.
- Final Release build and strict ad hoc signature verification passed. [Build log](../evidence/ux-20261012/integrated-release.log). Artifact: `macos-app/dist/LocalClip.app`.
- `git diff --check` passed.

Concurrent changes to `SettingsWindow`, the settings host, and the visual probe were detected during final verification. They were preserved. The combined source passed the full Debug suite and Release build, and all five settings pages were rendered and inspected at their fitted heights. Source hashes stayed unchanged during final verification; the packaged executable has the same Mach-O UUID and section contents as the resulting Release binary (code signing changes the whole-file hash). The earlier live interaction checks predate these window-sizing changes; live resizing animations were not independently rechecked.

The live synthetic-store sample recorded approximately **53 ms from input change to AppKit drawing** and **352 ms cold launch to drawing**. This is one sample, excludes input transport/GPU scanout, and does not establish large-history latency, frame rate, memory, or battery guarantees. The lazy list and existing asynchronous content loading were retained. [Timing boundary and values](../evidence/ux-20261012/gui-samples.json).

The computer-use drag attempt reached the native drag-start path but was cancelled; its events reported no held mouse buttons. This does **not** establish successful physical drag-and-drop. Native hosted routing passed separately. External target-app paste receipt, multi-monitor transitions, prolonged performance, and physical VoiceOver use were not revalidated in this pass. No auxiliary permission was granted to the test app.

The Release app uses the existing version metadata; it is a local updated build, not a published release. The existing source archive was not regenerated.
