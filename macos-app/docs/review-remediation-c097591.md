### Release measurements

Same machine and Release configuration. Search uses 5,000 synthetic records, 50-row pages, 30 sequential queries per case, identical content/scale with generated IDs/timestamps. P95 uses nearest rank. These are storage/test-host timings, not GUI first-frame latency.

| Case | Before p50 / p95 (ms) | After p50 / p95 (ms) |
|---|---:|---:|
| Fully indexed search | 24.846 / 25.838 | 25.806 / 26.930 |
| Missing-index fallback | 589.376 / 641.237 | 477.600 / 523.860 |
| 52 MiB batch output/rejection, 10 operations | 90.593 / 94.621 | 0.957 / 1.387 |

Indexed latency is about 4% higher in this small sample despite the 98.04% projection-byte reduction. It is not claimed as a speed improvement. Missing-index p50 improves about 19%, while yielding between batches; full-scale capture latency remains to be measured.

The output case intentionally changes behavior: before publishes the 52 MiB batch, after rejects all of it above the 50 MiB budget. It is not an equal-throughput comparison. Two opaque image representations and a fake pasteboard isolate loading/composition; this does not measure image decoding or real pasteboard daemon memory. At 5 ms sampling, test-process maximum physical footprint was 58.86 MiB before and 37.36 MiB after; maximum per-operation increase was 26.06 MiB and 0.016 MiB. Sampling can miss peaks and is not RSS or a memory ceiling.

## Release decision, risks and rollback

**Do not label native acceptance complete.** See [native-release-gates.md](native-release-gates.md) for required interactive tests, performance cadence and exact-SHA maintainer evidence/waiver. No repository acceptance record has been written and no release was attempted. This intentional gate blocks tag publication until that record exists.

For this task the user explicitly requires actual acceptance, **not a waiver**, and no publication. The [follow-up report](native-acceptance-2026-10-14.md) supersedes earlier broad statements that all target receipt remained unobserved: plain/rich/image/file Copy followed by manual target paste now has evidence. Direct-paste receipt still does not. Fresh non-interactive runs passed 90 and 46 functions respectively, with 9 and 2 gated skips; these do not replace a full current-code native run.

Remaining work includes physical keyboard/IME/VoiceOver and Quick Look races, real target receipt/drag-and-drop, slow AX first-frame profiling, slow-volume previews, large rich-text/mixed output resource tests, 100k/concurrent capture search, long-duration memory/idle monitoring, supported Xcode/OS matrix, and actual tag artifact/signature verification. No nightly runner or 2–8h soak is implied by the local measurements.

No schema migration or persistent representation change is introduced. Original TIFF/RTF/HTML, file references, search literal/order rules, protection, privacy filters and target checks remain. New budget failures are explicit and preserve the clipboard/history. Search fallback uses temporary disk space and may restart after atomic store replacement. File previews trade extra metadata checks for freshness; slow-volume behavior needs measurement.

Rollback is a scoped reversal of this remediation's source/workflow changes, preserving concurrent UI changes and user data. Do not reset the whole working tree or delete History. For future schema evolution, follow [schema-recovery-contract.md](schema-recovery-contract.md). Tests and raw evidence use isolated synthetic data and can be retained without touching the installed application.
