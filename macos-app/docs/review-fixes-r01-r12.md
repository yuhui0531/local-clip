## Changes and regression coverage

### R-01 / R-06

`HistoryViewModel.swift` starts refresh before loading categories/settings. Those cheap facts remain a query-signature barrier so a deleted category cannot publish a stale result. Source suggestions load when filters open or a capture reports an unseen source; concurrent requests coalesce and await list publication. A failed metadata read is retried rather than poisoning subsequent refreshes. Settings visibility controls usage reads; quota/retention/delete changes refresh capacity and correct usage. `AppDelegate.swift` forwards Settings-window visibility. `CaptureCoordinator.swift` reports pending source attribution without an extra list refresh.

`change()` and `saveCategory()` rely on the store change event. `ReviewMetadataLoadingTests` covers lazy sources/usage, unseen sources, metadata-read failure recovery, hidden changes, deleted categories, changed-only capture notices and a single window query per mutation. Existing pagination, selection, expiry and optimistic deletion tests remain enabled.

### R-03

`HistoryListState.swift` holds items, cursor, loading, selection and scroll restoration in one published snapshot. The input is independently observable. A derived footer snapshot only publishes its consumed values. Selection metadata is stored separately and only notifies the footer, so its delayed read does not invalidate the history strip. The logical query guard becomes busy immediately; the visual spinner appears only after 100 ms. `queryID`, revision and signature guards remain intact. Metadata publishes into the footer while the original selection remains authoritative.

`HistoryStore.swift` caches the complete prior candidate IDs only up to 5,000, for normalized literal extensions with unchanged filters and revision. It falls back to a full search when the set is incomplete, filters change or a commit lands. It caches successful index-completeness checks per revision. Context cache entries are bounded snippets (256 entries, each at most 4,096 UTF-8 bytes), cleared on revision change and consulted only after current SQL ranking/filter/visibility checks. Indexed normalized text avoids normalizing an entire long body again for a short hit context. Missing-index fallback still extracts original supported representations.

Raw final extended-query samples: [extended-search-results.json](/Users/ronny/VscodeProjects/rea/macos-app/evidence/review-fixes/r01-r12-20261011/final-extended-search-indexed-context/extended-search-results.json).

`SearchRetentionQuotaTests.extendedLiteralSearchPreservesFullRankingAndContext` compares the ten specified literals and extensions against an uncached full-search oracle, including order, long-tail context, source-only hits, source changes and revision/filter invalidation. NFC/NFD, embedded NUL, punctuation and missing-index tests remain enabled. Context extraction is also checked against independent normalization from original text. `HistoryLoadingTests` covers an immediately superseded scrolled query and final selection/zero-offset restoration. `ReviewMetadataLoadingTests` verifies atomic publication, no chrome invalidation, delayed spinner ownership and no extra strip publication when selection metadata arrives.

Several measured UI experiments did not meet the hosted gate and were reverted: a completed-highlight cache, scroll reset suppression, removing card GeometryReaders and combining highlighted lines into one Text. Scratch-only attribution with preview content omitted still measured 101.82 ms hosted P95, so preview construction alone does not explain the miss.
