# LocalClip 性能基线

基线基于 `main` 的 `5592665`（v0.3.83），加 M1 计时与基准夹具，使用当前 SQLite 原库事务提交协议。Release、arm64、macOS 15.7.5（24G624）、MacBook Pro Mac14,5、Apple M2 Max 12 核、32 GB。两个测试套件串行执行，未隔离其他进程。测试仅使用临时库及合成数据。

| 指标及负载 | 样本数 | P50（ms） | P95（ms） | 最大值（ms） |
| --- | ---: | ---: | ---: | ---: |
| M3 · 重复入库 50 MiB 合成图片载荷 | 100 | 139.02 | 161.49 | 163.89 |
| M3 · 采集约 50 MiB 临时文件副本 | 100 | 136.51 | 161.67 | 164.59 |
| M3 · 达到配额后调用 `canCapture` | 100 | 1547.12 | 1574.46 | 1577.36 |
| M3 · 对约 260 MiB 库调用 `integrityCheck` | 100 | 60.03 | 85.84 | 88.72 |
| M4 · 50,000 条短文本 | 10 | 117.14 | 135.08 | 135.08 |
| M4 · 1,000 条 × 1 MiB 文本 | 10 | 418.45 | 468.74 | 468.74 |
| M5 · 260 MiB 库（273,371,136 字节） | 10 | 110.91 | 116.44 | 116.44 |
| M5 · 2 GiB 库（2,152,419,328 字节） | 10 | 862.20 | 879.38 | 879.38 |

P50 取中位数，P95 取 nearest-rank，保留全部计入样本的测量值。原始样本由测试逐条输出，包含最慢样本。旧协议数据见 [历史性能记录](performance-history.md)。

- **M3** 每种场景在 actor 开始执行一次重操作后发起 100 次 `metadata`，计量调用至返回，包含排队、查询以及并发元数据请求间的争用。图片载荷为存储层合成字节，无解码。配额由稀疏临时文件填至上限，包含删普通记录再回滚的探测。配额探测的总延迟不能单独归因于 `usage()` 的聚合查询。
- **M4** 交替查首页和末页，查询计总数，搜索词互不构成前缀。长文本负载命中 100 条，短文本命中 5,000 条，单页 50 条。两组 P95 均高于报告建议的 80 ms。
- **M5** 各反复打开同一合成库 10 次，计量 `HistoryStore.init` 至 `recover()` 返回。未清除系统页缓存，未采集冷启动样本。

表中历史数据来自临时 SwiftPM 副本，当时排除了五个依赖 Debug 探针的测试文件。现在仅依赖这些探针的用例在 Debug 编译，其余用例与基准可直接从仓库运行。

```sh
LOCALCLIP_STORAGE_BASELINE=1 rtk proxy bash macos-app/scripts/test.sh -c release --no-parallel --filter StorageBaselineTests
```

## 2026-11-14 M1 隐藏面板对照

使用两份当前代码的临时副本，分别测现有实现和仅将 `prepareSurface` 的等待条件恢复为 `if destination != nil` 的对照实现。每轮用 3,000 条合成短文本，每种场景先冷打开一次，记录其后的 50 次。准备完成场景先确认关闭已登记首屏准备，再等待 `preparingFirstScreen` 和 `historyBusy` 都为 false。即时场景在关闭完成后立即呼出，保留最多 80 ms 的首屏等待。

计时从热键回调到隐藏面板完成布局并触发提交探针。正式埋点结束于 `makeKeyAndOrderFront` 返回。隐藏测试绕过真实 AX 目标读取与置前，显示器首帧、淡入和真实按键不在测量范围内。旧版 M1 两次运行的条件不同，此处以同条件对照替代。

```sh
LOCALCLIP_PANEL_BASELINE=1 rtk proxy bash macos-app/scripts/test.sh -c release --no-parallel --filter HistorySubmissionBaselineTests
```

首屏已准备时，移除等待后各轮 P50 为 6.01–6.36 ms，对照为 39.29–40.43 ms，配对差为 32.93–34.34 ms，高于同组轮次波动。每组 150 个样本按 5 ms 分箱，准备完成场景未见分离的双峰。立即呼出时两组均出现两个聚集区，无等待组主要在 70–75 ms 与 100–110 ms，有等待组主要在 105–115 ms 与 135–145 ms。立即呼出时的 P50 跨轮波动更大，支持首屏准备时序影响旧基准的推断。基准未单独计量等待分支的耗时或命中次数。

## 2026-11-14 M3 满配额采集探测

| 调用 | 样本数 | P50（ms） | P95（ms） | 最大值（ms） |
| --- | ---: | ---: | ---: | ---: |
| 首次，完整预演 | 100 | 1568.44 | 1591.16 | 1593.55 |
| 紧接第二次，缓存命中 | 100 | 27.25 | 49.65 | 52.29 |

每组同时发起 100 次 `metadata` 请求，测量从请求到返回的总时延，包含元数据请求之间的排队。首次仍执行原预演事务，紧接的第二次在库、占用和配额均未变时命中缓存。内容变化后，下一次仍需完整预演。

```sh
LOCALCLIP_STORAGE_BASELINE=1 rtk proxy bash macos-app/scripts/test.sh -c release --no-parallel --filter metadataDuringStorageOperations
```

原始样本与运行日志见 `macos-app/evidence/automated/20261114-review-fixes-release/`。每份 Release 副本第一次编译，后续轮次复用同一构建。两份副本固定于同一源码快照，测量期间工作区另有紧凑文件卡片布局调整，由 Debug 回归覆盖。
